Fresh Moves + Just Expressions

Just Expressions puts its eyebrow overlay planes one thousandth of a unit in front of the hat layer. That is far too small for the depth buffer to resolve, so whether eyebrows or sunglasses win changes with camera angle. This patch moves the eyebrows back and leaves everything else alone. Back to the editor

The problem, measured

The player model has three parallel planes at the front of the face:

SurfaceFront zGap to next
Head face−4.0000.501
Eyebrow overlays (8 boxes)−4.5010.001 ← too small
Hat layer, where skin glasses live−4.500—

A 0.001 gap is below the precision of the depth buffer at normal view distances. The two surfaces therefore alternate, which is what produces edges that shimmer and move as the camera turns. This is Just Expressions issue #5, reported for Minecraft 26.2 and still open.

What this does and does not do

It changes the pack format so the game accepts the pack without a warning, and it does nothing else. Every model file inside is byte-identical to Fresh Moves and Just Expressions as their authors ship them.

SurfaceValue
Head face−4.000
First-layer brows−4.150
Second-layer brows 5–8−4.550
Brow row 9−4.150
Hat layer / your glasses−4.500

Earlier versions of this page claimed a glasses fix. They were wrong. Moving the second-layer brows from −4.550 to −4.350 did not close a coplanar gap: these boxes are 0.25 units deep, not flat planes, so translating them moves a solid slab. In game it showed as bars standing off the face. That edit has been reverted and the packs ship the original numbers.

Eyebrows can still draw over sunglasses. That is an open upstream issue and this download does not solve it. What it does solve is the pack being rejected or warned about on newer versions.

Download

One file per Minecraft version, because the pack format changed. Pick the one matching your game version.

Install

  1. Set the ETF option first. Both packs require it and it is off by default. Options → Resource Packs → click the creeper face button → Textures → Player skin settings → set Allow skin transparency to All skins. Without it, ETF forces the skin's alpha channel fully opaque, which breaks the animated eyes and hard-cuts the edge of any semi-transparent layer.
  2. Remove the old packs. Delete or disable Just Expressions, Fresh Moves, and any earlier version of this patch. Two copies of the same model only fight.
  3. Drop the zip into resourcepacks and enable it in the game.
  4. Check the mods. This needs Entity Model Features 2.0.2 or newer and Entity Texture Features 6.0.1 or newer. Delete AlphaSkins and CustomSkinLoader if you have them; both are obsolete and cause black eyes.
  5. Restart the game if the eyes still look wrong. ETF caches skin data.

What is inside

  • assets/minecraft/emf/cem/player.jem and player_slim.jem, the models EMF actually loads
  • assets/minecraft/emf/cem/player_face.jpm and 21-2/…/player_face.jpm, unmodified. Their brows are a separate set (r_brows at −4.05) that is already clear of the hat, so they are shipped as-is.
  • assets/minecraft/optifine/cem/, the same models under Fresh Moves' own path, so both loader layouts work
  • the eye texture, and pack.mcmeta written for the pack format your client expects

EMF reads emf/cem in preference to optifine/cem, so Just Expressions' model is the one that renders when both packs are installed. Both paths are shipped so the same zip works either way.
